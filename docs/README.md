# yappy documentation

A map of what is here, and who each document is for.

Some of these are published at `https://docs.yappy.gg`, generated by
`node web/tools/build-docs.mjs`. The rest stay in this repository. yappy is not
open source, and the operator runbook and architecture notes describe how the
service is built and run rather than what we are offering to build on. The split
is declared in `SECTIONS` and `UNPUBLISHED` at the top of that script, and the
build fails if a new document is in neither.

## Published: for developers building on yappy

- **[QUICKSTART.md](QUICKSTART.md)** takes you from no account to a bot that
  answers a slash command and handles a button press. Start here.
- **[BOTS.md](BOTS.md)** is the bot developer guide in depth. Registering,
  authenticating, embeds, charts, live cards, components, slash commands,
  signed webhooks, and the permission model.
- **[BOT_API.md](BOT_API.md)** is the endpoint reference scoped to what a bot
  token may call, and an explicit list of what it may not.
- **[PERMISSIONS.md](PERMISSIONS.md)** is the bitfield: every bit, how a
  member's effective permissions are computed, and how rank differs from
  permission.
- **[ERRORS.md](ERRORS.md)** is the error envelope, every code by status, the
  rate limits, and how to retry without making things worse.

## Internal: for operators running an instance

- **[DEPLOY.md](DEPLOY.md)** takes a bare VPS to a running instance: DNS, the
  firewall, the environment file, `docker compose up`, and seeding the yapper
  bot.
- **[MODERATION.md](MODERATION.md)** is trust and safety operations: making
  staff, the Yappy Staff space, where reports go, and how suspensions work.

## Internal: for understanding the system

- **[API.md](API.md)** is the full REST surface, including the endpoints only
  our own clients and the portal use.
- **[REALTIME_PROTOCOL.md](REALTIME_PROTOCOL.md)** is the client WebSocket
  contract: opcodes, the resume handshake, and the events pushed over the
  gateway. Third-party bots use webhooks, not this.
- **[ARCHITECTURE.md](ARCHITECTURE.md)** is the why: one Postgres and no Redis,
  the gapless `seq` counter, fan-out, authentication, the permission model,
  media, calling, and what is deliberately not built.
- **[../packages/db/sql/0004_partitioning.sql.md](../packages/db/sql/0004_partitioning.sql.md)**
  is the partitioning plan for when the messages table outgrows a single table.

## Conventions across the docs

- Errors are always `{ "error": { "code", "message", "details?", "retryAfter?" } }`.
  Switch on `code`, never on `message`. Messages are copy and will change.
- Permission bitfields travel as decimal strings, because the field runs past
  the 2^53 limit of a JavaScript number. Parse them as big integers.
- Three token types exist and are not interchangeable: an account access token
  (`Bearer`), a bot token (`Bot`), and a portal session token (`Bearer`, but
  accepted only by `/portal/*`). Each is rejected everywhere it does not belong.
